# H2O_PBE0_pair_screen_off

## 1. 被测功能

incore RI-J/RI-K 内核的 AO 对（basis pair）筛选。筛选由 `[ctrl.ri_jk]` 的
`pair_screen_threshold` 控制，作用在已存储的对称三中心张量 `rimatr`（形状 `[nbaspar, naux]`）
的行方向，判据是相对阈值：

- 每个 AO 对有静态上界 `q_p = max_P |R[p,P]|`，由几何决定，只算一次。
- J 的密度缩并用 `|w_p| q_p`（`w_p` 为密度权重，对角对取 1 倍、非对角对取 2 倍）与本步最大的
  对界值比较，低于阈值倍数者丢弃。J 的回缩并用 `q_p` 与最大的 `q_p` 比较。
- K 用 `q_p max(W_mu, W_nu)`（`W_mu = max_i |C[mu,i]|`）与本次迭代最大的对界值比较。

保留下来的对里，K 只对它们张成的活跃 AO 子集做缩并与 `dsyrk`。

## 2. 触发条件

本用例**不写** `pair_screen_threshold`，取值 0.0，即关闭筛选，走原有的未筛选内核
（J 为两次 `dgemv`，K 为逐辅助基的稠密 `dsymm` 与 `dsyrk`）。它同时锁住“缺省不改变既有数值”。

## 3. 覆盖点

- 缺省分支：关键词缺失时不得启用筛选。若缺省值被改成非零，本用例的能量会偏离参考值。

## 4. 对照

参考值由 release 构建生成，对应未筛选路径。同一体系、同一基组下 `H2O_PBE0_pair_screen_on`
（相对阈值 1.0e-4）给出 -76.2919377798 Ha，与本文用例相差 1.57e-02 Ha，说明筛选确实生效，
两条路径都能被回归锁定。
